# 저장 공간 설정

설정 → 저장 공간에서 디스크 잔여 용량, 서비스 파일 총량과 종류별 사용량,
현재 로그인 사용자의 작업별 입력·중간·결과 파일 크기를 확인합니다.
사용량은 조회 시점의 파일 크기 합계로, 파일시스템 실제 할당량과 다를 수 있습니다.
전체 서비스 합계는 모든 사용자의 파일을 포함하며 작업 상세와 정리는 본인 작업만 허용합니다.

## 정리 동작

- 중간 파일 비우기: COMPLETED 작업의 work 하위 디렉터리 및 임시 미디어·로그를 삭제합니다.
  work 루트의 JSON/SRT/SMI/ASS/VTT는 자막 편집·미리보기용으로 보존합니다.
  원본, 최종 결과물과 작업 기록은 유지합니다.
- 선택 작업 전체 삭제: COMPLETED/FAILED/CANCELLED 작업 디렉터리 전체를 삭제합니다.
  UI에서 선택한 작업 수와 예상 크기, 결과물 삭제 여부를 확인한 후 실행합니다.
- 작업 실행 및 상태 잠금을 획득한 뒤 소유자와 상태를 다시 확인합니다.
  진행 중/검토 대기, 다운로드 중인 작업은 보호합니다. 실패·취소 작업의 중간 파일은
  재시도에 필요하므로 전체 작업 삭제로만 제거합니다.
- 보관함 원본과 얼굴 합성 세션은 이 기능에서 삭제하지 않습니다.
  영상 보관함의 기존 삭제 기능을 사용하면 참조 중인 영상은 보호됩니다.
- 심볼릭 링크와 Windows junction/reparse point는 집계에서 제외하며,
  해당 링크가 들어 있는 작업은 정리를 거부합니다.
- 한 요청에 최대 100개 작업만 처리합니다. 일부 실패 시 결과별 상태를 반환하며
  성공적으로 제거한 파일의 논리적 크기를 표시합니다.

## Docker에서 Windows 실제 디스크 조회

기본 Compose는 `./scripts` 폴더를 API에 `/host-disk-probe`로 읽기 전용 마운트합니다.
`HOST_DISK_PROBE_DIR`에 기존 폴더를 지정하면 해당 폴더가 있는 디스크를 조회합니다.
Docker 가상 디스크를 다른 드라이브로 옮겼다면 그 드라이브의 폴더를 지정하세요.
API의 `HOST_DISK_PROBE_PATH`가 없거나 조회할 수 없으면 내부 저장 파일시스템 수치로
대체하며, UI에서 실제 호스트 용량과 다를 수 있음을 알립니다.
Native API는 작업 저장 디스크의 용량을 바로 표시합니다.

Docker 볼륨 파일을 지우면 볼륨 내부 공간은 확보되지만, Windows의 VHDX 파일은
자동으로 축소되지 않을 수 있습니다. 이 기능은 VHDX 압축, Docker 이미지/모델 삭제를 하지 않습니다.
Compose 변경을 적용하려면 API 컨테이너를 다시 생성해야 합니다.

API: `GET /api/settings/storage`, `POST /api/settings/storage/cleanup`
정리 요청: `{"mode":"temporary","job_ids":["32자리 작업 ID"]}`.
전체 삭제는 mode `jobs`. 기존 설정 인증·CSRF·동일 출처 정책을 적용합니다.
