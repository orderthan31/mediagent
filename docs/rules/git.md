# Git 커밋·푸시 규칙

## Common

### 커밋

다음 중 하나에 해당하면 커밋한다.

- 사용자가 직접 커밋을 요청했을 때.
- 특정 태스크를 완료했을 때.

### 푸시

다음 중 하나에 해당하면 푸시한다.

- 사용자가 직접 푸시를 요청했을 때.
- 사용자가 지시한 태스크 묶음을 전체 완료했을 때.

여기서 태스크 묶음의 완료는 묶음에 포함된 태스크를 한 사이클 모두 진행한 상태를 뜻한다. 기술적 한계나 예외 등으로 완수하지 못한 태스크가 남아 있더라도, 전체 사이클을 마쳤으면 푸시 조건을 충족한다.

## Special

### 대상과 보존

- 개발 대상은 canonical 저장소 `orderthan31/mediagent`의 `renewal`이다. 제품 표기는 `mideagent`이며 표기 변경으로 저장소나 기본 브랜치를 바꾸지 않는다.
- 현재 WIP·미추적 소스와 원격 ref를 확인한 뒤 명시 경로만 stage한다. `git add --all`, reset, force push, 히스토리 재작성과 master 통합은 하지 않는다.
- 일반 커밋과 푸시 전에는 실제 변경 범위·비밀정보·생성물·테스트 결과를 확인한다. 부분 완료/미검증은 커밋이나 문서에서 명시하고 기능 완료로 보고하지 않는다.
- GitHub App 인증을 사용하고 토큰을 URL·명령 출력·로그·커밋에 넣지 않는다. 일반 push 후 정확한 원격 브랜치 SHA를 읽어 확인한다.
