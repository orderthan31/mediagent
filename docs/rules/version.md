# 버전 관리 규칙

## Common

### 버전 증가 시점

- 버전은 태스크 수행이나 완료 때마다 올리지 않는다.
- 정식 빌드가 성공했을 때 버전을 올리고 확정한다. 디버그 빌드나 실패한 빌드로는 버전을 올리지 않는다.

### 버전 번호

- 버전은 `x.x.x` 형식의 세 자리 숫자로 관리한다.
- 첫째 자리는 사용자가 올리라고 직접 지시한 경우에만 올린다. 지시 전에는 올리지 않는다.
- 둘째 자리는 굵직한 신규 기능을 추가하거나 사용자가 직접 지시한 경우에 올린다. 기존 기능의 수정만으로는 올리지 않는다.
- 셋째 자리는 자잘한 수정과 보정에 적용한다.

## Special

### 미디에이전트 버전

- 현재 renewal의 타입 검사·Vite build·격리 테스트는 개발 검증이며 정식 릴리스 빌드가 아니다. 이 문서 이관으로 package 버전을 임의 변경하지 않는다.
- 굵직한 신규 기능은 독립 에이전트 실행, workflow 기반 처리 또는 저장소/실행 구조의 제품 단위 확장이다. 캐릭터·게임 모드 기준은 적용하지 않는다.
- 정식 버전 확정 시 실제 배포 대상을 지정하고 구성요소 버전과 소스 식별자를 함께 기록한다. [패치노트 템플릿](../templates/patch-note.md)을 사용한다.
