# 파이프라인 속도와 안정성 점검

2026-09-29 운영 데이터의 파일 크기와 메타데이터만 읽고, 합성 영상으로 측정했다.
사용자 영상의 디코딩이나 실제 LLM 요청은 하지 않았다.

## 확인된 병목과 수정

| 구간 | 기존 비용 | 변경 |
| --- | --- | --- |
| 큐 접수 | 공용 잠금 즉시 실패, 용량 검사 중 경합 | 제한된 잠금 대기, 요청 ID 유지 재시도, 최신 용량 감사 활용 |
| 워커 시작 | 일반 작업은 최대 5초 폴링 대기 | 기존 깨우기 신호를 모든 QUEUED 저장에 연결, 신호 실패 시 폴링 유지 |
| 영상 분석 | 첫 제어 콜백에서 저장소 전체 재귀 검사 | 최신 감사 + 활성/최근 변경 작업의 예약량 + 접수 원장으로 보수적 추정 |
| 작업 공간 예약 | 공용 접수 잠금 안에서 전체 재귀 검사 | 최신 감사 활용, 예약 증가·물리 여유 공간 검사 유지 |
| 작업 중 제어 | 주기적인 전체 저장소 검사 | 감사 결과 활용, 감사가 없거나 600초 이상 오래되면 실제 집계 |
| 전체 용량 집계 | 파일별 반복 경로/상태 조회 | scandir 항목 메타데이터 재사용, 심볼릭 링크 제외 |
| 자막 입력 접수 | 작은 JSON 저장에도 전체 용량 검사 | 접수용 용량 검사 재사용 |
| 인코딩 후 검사 | 영상·오디오 전체 CPU 디코딩, 진행률 없음 | 전체 검사 유지, FFmpeg 실제 진행률 표시 |

할당량 추정에는 활성 작업의 예약량 전체를 더한다. 따라서 여유 용량이 적을 때는
실사용량보다 일찍 거절할 수 있다. 안전한 저장 용량 제한을 위해 의도적으로 보수적이다.
최근 감사가 없어도 용량 검사를 생략하지 않는다.

## 측정 결과

약 99.1 GB 라이브러리를 읽기 전용으로 마운트한 별도 워커 컨테이너에서,
동일한 10초 720p 합성 영상으로 `scripts/benchmark-pipeline-io.py`를 실행했다.

| 구간 | 개선 전 | 개선 후 |
| --- | ---: | ---: |
| 라이브러리 전체 크기 집계 | 11.493초 | 2.222초 |
| 영상 분석 + 첫 용량 확인 | 11.795초 | 0.451초 |
| 오디오 추출 | 0.202초 | 0.202초 |
| 필터 없는 오디오 전처리 | 0.003초 | 0.003초 |
| 출력 전체 디코딩 검사 | 0.201초 | 0.202초 |

별도 30초 1080p HEVC 합성 영상의 전체 디코딩은 CPU 0.970초, CUDA 1.189초였다.
이 짧은 샘플만으로 GPU를 기본값으로 바꾸지 않았다. 코덱·해상도·길이에 따라 결과가
달라지며 실제 긴 영상의 처리시간을 이 값으로 보장하지 않는다.

최종 API 이미지에서 동시 업로드 12건은 6.15초에 모두 큐 등록됐다. 접수 잠금을
일부러 6초간 점유한 별도 시험에서는 일시적 busy 응답 12회를 동일 요청 ID로
재시도해 10.95초에 12건 모두 등록됐고 중복은 없었다. 서버의 제한된 대기를
넘기는 경합은 정상적으로 발생할 수 있으므로 이를 사용자의 최종 실패로 취급하지 않는다.
외부 모델을 대체한 합성 영상 E2E는 최종 워커 이미지에서도 통과했다.

## 남아 있는 실제 작업 비용

- FFprobe는 메타데이터를 읽지만 오디오 추출·무음 탐지·최종 무결성 검사는 미디어를 처리한다.
- 얼굴 합성은 청크 생성 전 전체 시간축 검사, 청크별 검증·체크섬, 최종 연결 후 검사가 있다.
  단순 UI 상태 확인이 아니며 파일 길이에 비례할 수 있다.
- 전사·번역은 기존 요청별 진단·재시도 기록을 유지한다. 이번 측정은 외부 모델 속도를 포함하지 않는다.
- 입력 복사·체크섬은 파일 크기에 비례한다. 불변 입력 보장 때문에 임의로 제거하지 않았다.
- GPU 작업 실행은 계속 순차 처리한다. 접수 지연 개선과 병렬 GPU 실행은 별개의 문제다.

## 계측

작업 메타데이터의 `stage_durations_seconds`는 상태가 바뀔 때 직전 단계의 시간을
누적한다. 같은 상태의 진행률 갱신은 시작 시각을 초기화하지 않는다.
새 상태 전환부터 기록되므로 기존 완료 작업의 시간을 소급 생성하지 않는다.

공통 FFmpeg/FFprobe 실행기는 작업 디렉터리의 `process-timings.jsonl`에 실행 시간,
제어 콜백 시간, 종료 코드를 남긴다. 제어 시간은 실행 시간에 포함되며, 두 값을
단순히 빼서 정확한 CPU 사용 시간으로 해석하면 안 된다. 명령 인수·파일명·LLM 요청
내용은 기록하지 않는다. 파일은 512 KiB에서 이전 파일 하나만 남기고 순환한다.
계측 기록 실패는 미디어 처리 성공을 실패로 바꾸지 않는다.
