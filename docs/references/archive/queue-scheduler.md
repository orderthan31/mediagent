# 작업 큐·스케줄러·복구 개선

## 사용자 동작

전체 작업 화면의 대기 큐에서 위/아래 이동, 가장 먼저 처리, 선택 취소,
새 작업 시작 일시정지/재개를 제공한다. 설정은 현재 계정에만 적용된다.
일시정지는 진행 중인 작업을 중단하지 않는다. 순서를 우선하되 자원이 점유된
작업 뒤의 독립적인 작업은 먼저 시작할 수 있다. 실행 중인 작업을 선점하지 않는다.

다른 창에서 큐 설정이 변경되면 revision 충돌을 반환하고 최신 상태를 다시 읽는다.
일괄 취소는 모든 대상의 소유권과 잠금을 확인한 뒤 대기 상태만 취소한다.
이미 시작된 작업은 skipped로 반환하며 원본 파일은 삭제하지 않는다.

## 실행 한도

운영 Compose 기본값:

| 설정 | 값 | 의미 |
| --- | ---: | --- |
| MAX_CONCURRENT_JOBS | 3 | 워커 프로세스 내 동시에 진행할 작업 수 |
| MAX_GPU_JOBS | 1 | 얼굴 합성, VAD, 인코딩의 GPU 사용 한도 |
| MAX_IO_JOBS | 2 | 공통 FFmpeg/FFprobe 실행 한도 |
| MAX_LLM_JOBS | 1 | 전사·번역 단계에 진입할 작업 수 |
| MAX_ENCODING_JOBS | 1 | 기존 인코딩 슬롯 제한 |

LLM 작업 하나의 내부 구간 요청 동시성은 기존 정책을 따른다. MAX_LLM_JOBS는
개별 HTTP 요청 개수가 아니다. 작업별 공급자 인스턴스를 생성해 계정별 설정이
섞이지 않도록 한다. 자원 잠금은 프로세스 간에도 공유되며 대기 중 취소와 종료를 확인한다.
미리보기 엔진의 GPU 메모리는 인코딩/VAD 진입 시 해제한다. 얼굴 합성 실행과
그 엔진의 해제는 GPU 잠금으로 보호한다.

동일 자원을 기다리는 작업으로 실행 자리를 모두 채우지 않도록 접수 시에도 자원 종류를
확인한다. 일반 파일 처리와 외부 모델 대기는 다른 작업의 GPU 처리를 막지 않는다.
FaceFusion 전체 렌더는 청크 처리 동안 GPU 슬롯을 보유한다.

## 중단 복구

AUTO_RESUME_INTERRUPTED=true, MAX_AUTO_RECOVERIES=2가 기본이다.
새 복구 정책으로 실행된 작업만 대상이며 배포 전의 실패 기록을 자동 재실행하지 않는다.
실행 잠금을 획득하지 못하는 살아 있는 작업은 복구/수집 대상에서 제외한다.
사용자 취소, 원본 유실, 복구 횟수 초과는 자동 재시도하지 않는다.

외부 유료 단계는 실행 전 paid_operation_in_flight를 기록하고 체크포인트가 저장된 뒤
다음 단계로 넘어갈 때 해제한다. 중단 시 이 표시가 남아 있으면 자동 재전송하지 않고
수동 확인이 필요한 실패로 표시한다. 외부 공급자가 처리했지만 응답을 저장하지 못한
요청에 대한 정확히 한 번 실행은 보장할 수 없다.

인코딩 결과도 체크포인트에 크기/수정 시각을 저장한다. 검증 중 중단됐다면 같은 입력과
설정, 변경되지 않은 출력에 한해 인코딩을 재사용하고 무결성 검사를 다시 수행한다.
기존 전사·번역의 완료 및 부분 결과 캐시는 유지한다.

## 상태 저장과 조회

큐 설정과 순서는 SQLite 트랜잭션으로 저장한다. 작업 목록은 SQLite 색인을 사용하며
각 목록 조회에서 manifest의 수정 시각/크기/파일 식별자를 확인하고 변경분만 파싱한다.
삭제·손상·외부 변경을 반영하고 색인을 사용할 수 없으면 기존 JSON 조회로 돌아간다.
작업 실행 판단과 소유권 확인은 최신 JSON을 다시 읽고 상태 잠금으로 보호한다.
전체 작업 상태를 DB 하나로 이관한 것은 아니며, JSON은 복구 가능한 원본 기록으로 남는다.

Compose는 JOB_DATABASE_DIR=/data/job-databases와 job-databases named volume을
API·워커에 함께 마운트한다. Windows 영상 공유 폴더와 SQLite 쓰기를 분리한다.
스토리지 루트별로 서로 다른 DB 파일을 사용해 업로드 기록과 작업 기록을 격리한다.
백업에는 기존 jobs 데이터와 job-databases 볼륨을 함께 포함해야 한다.
색인은 재생성 가능하지만 큐 설정 DB를 없애면 일시정지/사용자 지정 순서는 초기화된다.

## 표시와 검증

현재 단계 경과 시간, GPU/파일/LLM 대기 이유, 단계별 누적 시간, 자동 복구 횟수를 표시한다.
진행률을 제공하는 출력 단계에서는 현재 단계의 자원 대기를 제외한 처리시간으로
남은 시간을 대략 계산한다. 이는 작업 전체 완료 시각 보장이 아니다.

- 단위/통합 테스트: 동시 큐 변경, 계정 격리, 일괄 취소, 자원 제한, 대기 취소,
  자원별 접수, 색인 갱신/재생성, 유료 요청 중단 보호, 복구 횟수 제한.
- 합성 영상 E2E: 전사·번역·인코딩 뒤 검증에서 중단 후 재개할 때 공급자 호출 수와
  인코딩 결과 수정 시각이 그대로 유지되는지 확인.
- scripts/verify-queue-scheduler.py: 격리 컨테이너의 합성 영상과 로컬 공급자 대체 응답으로
  전사가 기다리는 동안 인코딩·오디오 추출이 완료되는지 검증. 운영 영상과 외부 모델은 사용하지 않는다.
- scripts/seed-queue-ui.py: /tmp/queue-ui-jobs 전용 UI 기록. 실제 작업 실행 없이
  브라우저의 순서 변경·일시정지·재개·선택 취소를 검증한다.
