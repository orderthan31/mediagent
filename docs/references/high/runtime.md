# 리뉴얼 실행·보존 계약

이 문서는 현재 코드가 지켜야 하는 경계를 설명한다. 실행 승인서·배포 완료 보고나 후속 자동 개발 지시가 아니다. 제품 요구는 [제품 기획](../../plans/specs.md), 미완료 항목은 [현재 작업](../../plans/tasks.md)을 따른다. 과거 진행 보고는 Git 이력과 기존 감사 기록에 보존하며 현행 지시로 누적하지 않는다.

## 작업과 정의

- 새 작업은 선택한 입력·저장 workflow 버전·모델/후보·언어·옵션과 원본 참조를 snapshot에 고정한다. 읽기·재열기로 과거 정의나 당시 absent-policy 의미를 변경하지 않는다.
- 일반 요청 식별자와 작업·시도·결과 식별자를 구분한다. 같은 요청의 정확한 재전송은 기존 결과를 반환하고, 같은 ID에 다른 내용은 충돌로 거절한다.
- 공개 업무 에이전트가 내부 도구 순서와 완료 판단을 소유한다. 내부 도구를 새 업무 에이전트로 중복 노출하지 않는다.
- 모델 선택은 저장된 등록 ID/revision과 후보 순서를 따른다. 업무 코드의 특정 LLM 강제, 조용한 모델 교체, 옵션 무시는 허용하지 않는다.

## 승인과 외부 요청

- 계획 확인·동의 저장과 실행 진입을 분리한다. 서버가 현재 입력·남은 작업·설정과 동의를 결속하여 소비하고 중복 진입을 막는다.
- 사용하지 않은 동의의 만료와 사용된 실행 시도 기록은 다르다. 동일 요청 재전송으로 만료를 갱신하거나 같은 시도를 다시 발행하지 않는다.
- 모델 요청 전 지속 가능한 intent와 호출 예산을 기록한다. 알려진 실패의 지원 재시도와 응답·commit 불명을 구분한다. 불명은 자동 재호출·fallback하지 않는다.
- 선택된 모델별 시간 정보·입출력·구조화 응답과 요청 옵션을 검증한다. 키·주소·모델·transport·재시도 정책을 임의 옵션 JSON으로 덮어쓰지 못하게 한다.
- 외부 공급자의 과금 취소나 정확히 한 번 실행은 이 계약이 보장하는 기능이 아니다.

## 결과 수용과 취소

- CAS 파일의 실제 해시·크기·유형·출처를 검증한 뒤 결과와 상태를 확정한다. 파일 존재, 모델 응답 수신, 정상 단계 완료는 서로 다르다.
- DB 실행 세대와 현재 시도·입력·정의에 맞지 않는 늦은 결과는 정상 출력으로 채택하지 않는다. 원 사실과 격리 자료를 보존한다.
- 취소 이후 새 모델 요청·후보 전환·후속 단계를 시작하지 않는다. 진행 중 외부 요청을 소급 취소했다고 주장하지 않는다.
- 독립 가지의 완료 결과를 다른 가지 실패나 검수 대기로 삭제하지 않는다. 미선택·필수 실패·대기와 전체 완료를 구분한다.
- 복구는 지원된 새 작업과 출처 연결로 수행한다. 기존 불명 시도·승인·결과를 성공으로 덮거나 자동 replay하지 않는다.

## 음성·자막·영상

- 시간 정보는 원본 PCM frame과 검증된 clock·입력 SHA에 결속한다. 전처리·분할·원시각 복원 과정에서 누락·중복·범위 밖 시각을 성공으로 숨기지 않는다.
- 원문/번역 자막과 직접 수정본을 구분한다. 문구·시각·literal ID를 검증하고, 선택한 승인 revision의 정확한 내용을 후행에 전달한다.
- 저장·검수 승인과 이어 실행은 별도 행위다. 미저장 편집·충돌을 보존하고 변경된 입력이나 서빙에 과거 동의를 재사용하지 않는다.
- 원본 미디어와 accepted 산출물은 덮어쓰지 않는다. 새 수정본·별도 재렌더·중간/최종 출력은 출처를 연결해 보존한다.
- 입력·프레임·출력 bytes·호출 상한은 코드의 명시 정책을 따른다. 한 시험 영상 성공으로 모든 길이·코덱·GPU·모델 지원을 주장하지 않는다.

## 운영 경계

- 기존 원본·DB·키·백업·WIP·불명 처리·감사 기록과 미발행 결과는 보존한다. 서비스·DB·큐를 코드 정리 명목으로 삭제·재실행하지 않는다.
- 내부 TLS의 인증서와 신뢰 관계를 유지한다. 만료를 `verify=False`, 전역 HTTP 전환·새 공개 ingress로 우회하지 않는다.
- 새 시험·실제 유료 호출은 그 승인의 입력·모델·비용 범위에만 적용한다. 타 공급자·GPU·기존 작업 replay나 현재 배포 이전까지 확대하지 않는다.
- FaceFusion은 현재 개발 범위에서 제외하되 과거 코드·자료를 무단 삭제하지 않는다.
- 전체 테스트를 임의 운영 DSN·기존 브로커·실키에 연결하지 않는다. 통제 응답과 오프라인 검사, 실제 모델 처리·배포 검증은 별도로 보고한다.

## 실제 코드 위치

- 생성·승인·취소·수용: `apps/orchestrator/mideagent_orchestrator/execution.py`
- 배정·외부 전송: 같은 패키지의 `dispatch_queue.py`, `model_delivery.py`, `start_queue.py`
- 업무 소유권: `agents/mideagent_agents/`, workflow 해석은 orchestrator의 `workflow.py`
- 모델 역할·지속 상태: `runtime/model-executor/`, `agents/mideagent_agents/state.py`
- 결과 검증: `packages/shared/video_service/role_task_contracts.py`와 저장소·PostgreSQL 모듈

호환 모듈과 기존 정책 버전은 남아 있다. 현재 필요한 보존 경계를 확인하지 않고 이름·파일 수만을 이유로 제거하지 않는다.
