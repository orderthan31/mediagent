# mideagent 디자인 기준

## 목적

작업을 선택하고 결과를 받는 동선을 명확하게 만든다. 기획·개발 과정을 설명하는 문구로 불완전한 제품 흐름을 대신하지 않는다.

## 현재 상태

한결디자인 consumer 소스와 제품 Indigo 테마를 사용한다. 빌드 성공·목업 화면·브라우저 에뮬레이션을 실제 기능 완료나 사용자 최종 수용으로 표현하지 않는다.

## 주요 내용

- 27인치 FHD 데스크톱의 정보 밀도를 기본으로 하고, 좁은 휴대폰·펼친 폴드급 중간 폭에서도 사용할 수 있게 재배치한다. 실기기 수치를 추정해 고정하지 않는다.
- 진한 테두리와 카드 중첩보다 은은한 회색 구분선·정렬·간격·타이포 위계를 사용한다. 제품 토큰으로 밀도를 조정하고 공유 디자인 시스템을 무단 변경하지 않는다.
- GNB는 현재 위치와 페이지별 검색·주 행동, LNB는 작업·원본·워크플로우·에이전트·서빙·시스템과 관리자 계정 관리에 사용한다. 좁은 화면은 좌측 드로어, 충분한 폭에서는 접고 펼치는 탐색을 제공한다.
- 목록·상세·추가·편집을 하위 동선과 브레드크럼으로 연결한다. 작업 목록은 티켓·원본·워크플로우·상태·일시를 한 줄로 보이며 삭제·상세 오류·단계별 기록은 상세에 둔다.
- 기본 흐름은 입력 선택 → 저장 워크플로우 선택 → 설정·비용 확인 → 명시 시작 → 진행·검수 → 결과다. 내부 순차/분기/복구 실행기 종류를 사용자가 먼저 고르게 하지 않는다.
- 업무 에이전트와 제어 흐름은 캔버스에, 내부 도구의 진행·출력·로그는 해당 업무 상세에 둔다. 노드 설정은 저장·재열기와 실제 작업 설정이 일치해야 한다.
- 모델·공급자 목록은 간결한 행 링크로 구성하고 수정·사용 중지 등은 상세에서 수행한다. 내부 설정 revision을 외부 모델 가중치 버전으로 오해하게 하지 않는다.
- 일반 사용자의 원본·작업·직접 자막 편집과 관리자 기능을 구분한다. 메뉴 숨김만으로 권한을 구현했다고 보지 않는다.
- 반복 소개·가이드·WIP·검사 횟수·내부 식별자로 화면을 채우지 않는다. 실제 입력 제약·비용·실패·응답 불명과 비가역 행동의 결과는 해당 행동 가까이 짧게 유지한다.
- 로딩·확정된 빈 목록·조회 실패·이전 자료만 남은 상태를 구분한다. 실패를 정상 0건이나 성공으로 표시하지 않는다.
- 긴 목록·선택 노드·폼을 실제 휠/터치로 조작하고 하단 행동·팝오버가 본문이나 페이지 이동을 덮지 않게 한다.
- 캔버스 선택·이동·연결·해제·재연결·취소·되돌리기를 구분한다. 재연결 확정 전 원선을 보존하고 읽기 전용 작업 상세에서 정의를 수정하지 않는다.

## 미확정 사항

제품 CI는 확정되지 않았다. 임시 M 로고 제거를 유지하며 대체 로고를 임의 제작하지 않는다. FaceFusion 화면 확장은 이번 범위에서 제외한다.
