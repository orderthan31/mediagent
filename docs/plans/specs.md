# 미디에이전트 제품 기획

## 확정 추가 범위: 에이전트 전용 워크플로우와 실제 소스 계층

- 만들 것: 저장/편집/실행 캔버스에는 업무 에이전트만 둔다. 전사 → 한국어 번역 → 자막 영상 제작은 기본 프리셋이지 전체 업무의 고정 순서가 아니다. 음성 추출·전사·번역·자막 파일 제작·영상 변환 중 필요한 업무를 사용자가 연결한다. 분석·오디오 준비·구간 처리·자막 생성·인코딩·검사는 각 업무 에이전트가 소유하는 내부 도구다. 오케스트레이터는 에이전트 간 순서·배정·준비를, 에이전트는 자기 도구 선택·순서·결과 확인을 책임진다.
- 독립 업무의 소스 범위: 원문 전사에서 번역 없이 자막 파일을 만들거나 원문·번역 결과를 골라 SRT/SRT+SMI와 번인·소프트 자막을 선택한다. 자막 없는 영상 변환과 16kHz 모노 WAV 추출에는 모델을 요구하지 않는다. 저장한 버전의 언어와 모델 선택을 실행 설정의 정본으로 사용하며, 완료된 목표 결과를 내부 도구 선택 없이 조회한다. 현재는 단위 검증·개발 빌드 범위이며 실제 실행·다운로드 수용은 별도다.
- 사용: 영상과 등록 모델을 고르고 시작한다. 에이전트 상세에서 하위 도구의 진행·출력·실제 콘솔을 본다. 오류는 붉은 노드/이유로, 다음 실행기 실제 준비는 연결선의 ‘다음 단계 준비 중’과 대상 노드의 ‘준비 중’으로 구분한다. 내부 도구 준비는 에이전트 내부 진행이다.
- 소스: 기존 모노레포 안에서 오케스트레이터 구현·업무 agents·tools/툴허브·runtime/컨트롤넷을 실제 이전한다. 기존 import/CLI의 필요한 경계는 구현 없는 호환 모듈로 유지하며 원본 구현을 복제하지 않는다. 패키지·Docker·실행 진입점과 전후 트리를 함께 검증한다.
- 확인 경계: 새 작업·30/31 재실행·실모델/provider·유료/GPU 호출·새 검증계 없이 기존 개발계 빌드/시작과 화면, 네트워크 없는 결정/상태 회귀를 검증한다. 과거 작업 snapshot·실행·결과·불명 원장은 그대로 보존하고 과거 화면의 집계 투영과 새 실제 에이전트 실행 계약을 구분한다.
- 외부 통신: 승인 1565553471640572038의 범위로 전사/번역 연결부만 기존 API 외부망에 연결했다. DNS·인증서 검증 TLS 1.3은 양쪽 성공, HTTP 요청 0, 기존 작업/실행/호출 원장 동일. 이는 전사 완주·품질 검증이 아니다.
- 미검증/미결정: 실영상 새 흐름 완주와 콜드부트 전환의 신규 실행 실증은 승인 범위 밖이다. 없는 과거 HTTP 상태·콘솔을 만들거나 불명 호출을 자동 재호출하지 않는다.


## 최신 정정: 콘솔 원문과 멈춘 작업 표시

로그 탭은 시작·종료 이벤트가 아니라 실행기·모델 연결부의 실제 stdout/stderr와 예외를 보여준다. 태스크별로 구분하고 인증정보를 가린 뒤 컨테이너 밖에 보존한다. 과거에 출력·저장하지 않은 로그는 없다고 표시하며 재실행으로 만들지 않는다. 완료·오류·대기 태스크 모두 출력/로그 탭을 유지한다. 확정 오류와 응답 불명 보류를 작업·태스크 화면에 구분해서 보여주되 원래 실행 기록과 재호출 방지는 보존한다. 시험 작업은 생성 근거로 현재 목록에서만 삭제하고 사용자 작업 20·21·30·31과 불명·감사·결과 기록은 남긴다. 새 시험 작업이나 모델 호출은 하지 않는다.

## 이번 요청: 한국어 자막이 입혀진 영상

사용자가 영상을 넣으면 전사문을 만들고 한국어로 번역한 뒤, 한국어 자막이 화면에 입혀진 MP4를 받는다. 사람 검수 단계는 넣지 않는다. 태스크 상세에서는 출력과 실제 로그를 나눠 확인한다. 테스트 자료는 현재 목록에서 삭제하되 과거 작업을 확인하는 데 필요한 자료와 이력은 보존한다.

## 무엇을 만드는가

전사 에이전트는 오디오를 준비하고 필요한 구간을 나눠 시간 정보가 맞는 전사문을 완성한다. 번역 에이전트는 문맥과 자막 시간을 유지해 번역문을 완성한다. 오디오 추출, 구간 분리, 모델 호출과 결과 합치기는 이 업무에 쓰는 도구다.

## 사용자는 어떻게 쓰는가

원본·모델·언어를 선택하고 작업 시작을 한 번 누른다. 진행을 확인한 뒤 자막과 영상을 내려받는다. 에이전트 목록·상세에서는 맡은 일, 현재 상태, 사용할 수 있는 도구와 수행한 작업을 확인한다.

## 실제로 확인한 범위

기존 개발 환경의 작업 #29에서 전사·번역을 거쳐 자막과 영상이 만들어지고 다운로드되는 것을 확인했다. PC와 좁은 화면에서도 목록·상세를 확인했다. 정해진 시험 응답으로 처리 흐름을 확인한 것이며, 실제 모델의 인식·번역 품질을 확인한 것은 아니다.

## 아직 결정하지 않았거나 확인하지 않은 것

도구를 워크플로우 편집기에 직접 배치할지는 나중에 결정한다. 모델이 매 단계에서 사용할 도구를 스스로 고르는 방식은 추가하지 않았다. 기존 워크플로우와 진행 작업은 유지하며, 실제 유료 호출이나 GPU 실행은 별도 승인 없이는 하지 않는다.

## 목적

현재 확정된 제품 컨셉과 주요 기능을 관리한다. 세부 동작과 구현 상태를 중복 나열하지 않는다.

## 현재 상태

기존 개발 환경에 전사·번역 에이전트와 목록·상세가 연결됐다. 작업 #29의 자막·영상 다운로드까지 확인했다. 전체 기능의 동등성, 실제 모델 품질과 여러 컴퓨터에 나눠 실행하는 검증까지 모두 끝난 것은 아니다. 자세한 완료·미완료 항목은 태스크 문서에서 구분한다.

## 주요 내용

- 일반 사용자는 원본·작업과 브라우저의 자막 파일 편집을 이용한다. 워크플로우·에이전트·서빙·시스템·계정 관리 등 관리 영역은 관리자 전용이다.
- 직접 선택한 UTF-8 SRT 또는 단일 언어 SMI/SAMI는 문구·시작/종료 시각을 편집하고 별도 SRT/SMI 사본으로 받는다. 영상·작업·모델 선택 없이 이용하며 원래 파일과 accepted 결과를 변경하지 않는다. 선택한 수정본은 독립 자료로 저장하고 공유 인증 목록에서 다시 열 수 있다. 저장 성공은 서버 영속 저장·재조회 이후에 표시하며 다시 저장하면 새 수정본을 만든다. 여러 언어가 섞이거나 종료 시각이 없는 SMI는 추측해서 합치지 않는다. 기존 작업의 accepted revision 발행과 영상 재렌더는 별도 범위다. 독립 수정본 저장은 현재 소스 검증 범위이며 실제 저장소 권한·제품 저장 수용은 별도다.
- 로그인한 사용자 모두 원본과 작업·중간/최종 결과를 업로더·실행자와 무관하게 조회·사용·다운로드한다. 계정은 행위자/감사 기록이며 공용 미디어의 분리 경계가 아니다. provider credential과 관리자 설정 권한은 자료 공유와 별도로 보호한다.
- 새 Start로 승인된 자기 작업은 시작 대기열에서 일시정지·재개하고 시작 우선순위를 바꾼다. 첫 실행이 예약된 뒤의 작업과 후속 단계는 계속 진행하며, 순서는 완료 순서를 보장하지 않는다. 기존에 이미 승인된 작업·초안·과거 이력·응답 불명 시도를 자동으로 이 대기열에 넣지 않는다. 이 제어와 이미 승인된 시도의 전달 현황은 실행 관리에서 구분한다. 현재 새 시작 대기열은 소스·합성 계약 검사 범위이며 실제 저장·PG 예약·PC/390px 제품 수용은 별도다.
- 에이전트 활성화·비활성화와 실행 인스턴스 수 변경은 서버 전체에 적용하는 관리자 운영 제어이며 사용자별 설정으로 제공하지 않는다. 메뉴·화면 접근과 서버 API 권한을 같은 기준으로 제한한다.
- 작업 하나는 원본 하나와 저장한 워크플로우 하나의 실행이며 티켓번호로 식별한다.
- 각 실행의 ticket ID 아래 manifest와 단계별 중간/최종 산출물을 정리한다. 공용 원본은 별도 원본 ID 경로에 보존하고 티켓에서 참조한다. 기존 CAS object와 읽기 호환은 삭제하지 않는다.
- 원본은 검증된 미디어와 순수 메타데이터로 관리한다. 원본 상세를 작업·서빙 설정 화면으로 사용하지 않는다.
- 업로드 영상과 작업 결과 영상은 원본을 보존하며 웹 전용 WebM을 따로 만든다. 플레이어는 WebM을 재생하고 원본과 WebM은 각각 다운로드할 수 있다.
- 워크플로우는 독립 에이전트와 제어 노드의 조합이다. 각 에이전트는 개별 진입점과 입력/설정/출력 계약을 갖는다.
- 에이전트의 명령·결과 전달은 RabbitMQ adapter로 분리하고 전체 workflow와 다음 단계 판단은 애플리케이션이 소유한다. 공통 실행 의존성을 재사용하면서 에이전트별 실행·확장 경계를 유지한다. 운영 연결 완료를 뜻하지 않는다.
- 에이전트 상세에서 해당 종류의 활성화·비활성화와 실행 인스턴스 수를 관리한다. 얼굴교체 등 선택 에이전트를 사용하지 않아도 다른 에이전트를 이용할 수 있어야 한다.
- 같은 종류의 에이전트를 여러 인스턴스로 실행하고 작업을 분산할 수 있어야 한다. 이 운영 관리 요구는 확정되었으나 현재 CLI·정보 상세가 구현 완료를 의미하지는 않는다.
- 서빙에서 공급자 연결·등록 모델을 관리하고 모델을 사용하는 워크플로우 노드가 호환 자원을 선택한다.
- 모델을 쓰는 태스크는 주 모델과 선택적인 동적 폴백 목록을 추가·삭제·재정렬할 수 있다. 저장/재열기와 티켓 snapshot에 순서가 유지되며, 지원 능력·인증·비용 승인을 확인한 후보를 순서대로 유한 시도한다. 취소는 전환하지 않고 중단하며 전 후보 실패는 태스크 실패다. 각 후보의 시도/실패 이유/전환/최종 성공 모델을 기록한다.
- 작업 상세에서 고정된 정의와 입력, 노드 상태·결과·사람 검수·명시 실행과 복구를 관리한다.
- 처리 여부가 불명확한 작업은 원 사실을 성공/실패로 덮지 않고 별도 확인·판단 기록과 보류 사유를 제공한다. 명시 지원 범위와 종료 근거를 검증한 뒤에도 새 준비 작업만 연결하며 별도 계획/동의/실행 승인을 요구한다. 늦은 원 결과는 격리·다운로드로 보존한다.
- 웹/애플리케이션의 제어와 에이전트의 처리, DB의 메타데이터와 오브젝트 스토리지의 미디어를 분리한다.
- 공통 검수 화면이 데이터 계약을 해석한다. 새 에이전트마다 전용 검수 화면을 만들지 않는다.

## 미확정 사항

비활성화/축소의 기본 순서는 새 작업 배정 중단→진행 작업 완료→정상 중지다. 제한시간/강제중지·다른 역할/다중 슬롯 확장은 [미확정 기획](ideation.md)에서 구분한다. 관리자 전용 권한과 원 사실 보존·모호한 상태의 자동 해제 금지는 확정이다.

## 워크플로우의 LLM 선택
- 전사·번역 LLM의 정본은 워크플로우에서 고른 등록 모델 ID/revision과 요청 옵션이다. 업무 코드가 특정 LLM 이름·계열을 강제하거나 다른 모델로 바꾸지 않는다.
- 공급자 연결·키는 기존 계정별 저장 경계를 유지한다. 모델에 필요한 음성 입력·시간 정보·구조화 응답 기능이 없으면 사유를 알려 실행을 막는다.
- 공급자 변환은 모델 호출 툴 안의 LiteLLM SDK가 맡는다. 전사 분할·원본 시각 복원·한국어 번역·자막 번인과 에이전트 간 흐름은 기존 구조를 유지한다.


## 5178 기준 기능의 에이전트 범용화 — 현재 구현 범위
- 저장 자막에서 기존 workflow의 번역 에이전트 하나를 선택해 번역 전용 작업을 준비할 수 있다. 현재 normal job 계약에 필요한 원본 영상 맥락을 선택하고, 실제 고정 모델 후보·언어·요청 옵션·호출 상한을 확인한다. 준비는 읽기만 하며 전사나 영상 제작을 추가하지 않는다. 이후 명시적 새 작업 생성/시작만 별도 번역 작업을 만든다. 소스·오프라인 검증과 실제 공급자 호출·제품 수용은 구분한다.
- 저장한 독립 자막 수정본에서 원본 영상을 선택해 별도 자막 영상 작업을 준비할 수 있다. 기존 저장 workflow의 실제 자막 영상 에이전트와 지원 출력 옵션을 사용하며, 전사·번역을 필수로 다시 실행하지 않는다. 준비·미리보기는 읽기만 하고 사용자의 명시적 생성·시작이 별도 새 작업을 만든다. 원본·수정본·기존 작업 결과를 덮어쓰지 않는다. 현재 연결의 소스·오프라인 합성 검증과 실제 제품 생성·렌더 수용은 구분한다.
- 기준은 실제 `http://100.112.137.5:5178`의 별도 legacy 배포다. renewal이 아니며 OCI revision이 없어 특정 master SHA와 같다고 단정하지 않는다. 기준 서비스·기존 자료를 바꾸지 않고 비교한다.
- 제품 목표는 한국어 번인 프리셋 하나가 아니라 원본/별도 오디오/선택 자막을 사용한 오디오 추출, 전사, 번역, 자막 편집·내보내기, 자막 포함/미포함 영상 제작이다. 필요한 업무 에이전트만 연결하며 불필요한 전사·번역은 실행하지 않는다.
- 한국어 번인 프리셋은 유지하지만 업무 에이전트의 언어·모델·옵션·처리 순서 고정 제약으로 사용하지 않는다. 워크플로우 모델 revision/옵션과 명시 입력을 보존한다.
- 원본 보관·업로드/재개, 큐/취소/오류, 자막 시각·문구 검수와 SRT/SMI, 출력 받기, 모델/STT·저장소 설정, 얼굴 합성의 장면/범위/이어처리도 기능 대조 대상이다. 화면/API 경로 존재는 실제 실행 성공과 구분한다. 얼굴 합성·NVIDIA 등 GPU 실행과 유료/공급자 호출·장편 처리는 별도 승인 경계를 유지한다.
- 오케스트레이터는 에이전트 흐름을 관리하고 각 에이전트가 자기 업무의 툴을 소유한다. 툴을 캔버스 독립 구성원으로 복구하거나 버튼마다 이름뿐인 에이전트를 만들지 않는다. 기존 오류/실제 준비 연결선/출력·원문 콘솔을 유지한다.


## 음성 원본의 전사 준비

- WAV·MP3와 한정된 M4A(AAC) 음성 원본은 기존 원본 업로드·보관함·이어보내기와 다운로드를 이용한다. 실제 음성 형식과 길이를 확인하며 영상 미리보기로 표시하지 않는다.
- 원본 상세의 음성 전사 준비에서 저장된 워크플로우의 실제 전사 에이전트와 모델 버전·원문 언어·요청 옵션을 선택한다. 기존 새 작업 준비 절차로 전사만 구성하며 영상 분석·추출·번역을 요구하지 않는다. 작업 생성과 시작은 명시적인 사용자 동작이다.
- WAV·MP3의 기존 실제 등록·입력 준비 수용은 유지한다. 추가 M4A(AAC)는 현재 소스와 로컬 합성 probe·정규화 검사 범위이며 설치 제품의 입력 준비 수용과 실제 전사 실행은 별도다. 모든 녹음 형식 지원을 뜻하지 않으며 과거 영상 작업과 같은 영상에서 추출한 WAV 재사용 계약을 유지한다.


## 사진과 영상의 얼굴 합성 입력 확인

- 새 JPEG·PNG 사진은 기존 원본 업로드·보관함·원본 다운로드를 이용한다. 선택한 사진과 기존 대상 영상, 등록 실행기 버전, 지원 품질·영상 형식의 입력을 확인한다. 원본 사진 바이트와 업로더를 보존한다.
- 사진 형식·크기 확인은 얼굴 검출이나 합성 가능 판정이 아니다. 입력 확인과 실행 준비를 분리하며 인물 선택·승인된 미리보기·실행기 관측이 없는 현재 경로는 시작할 수 없다. 실행 안 되는 에이전트나 승인 버튼을 추가하지 않는다.
- 현재는 소스와 오프라인 합성 이미지/화면 검사 범위다. 실제 등록·설치 제품 입력 확인은 부모 수용 범위이며 얼굴 분석·GPU·미리보기·전체 합성은 실행하지 않았다. 기존 음성/자막 준비 수용과 별개다.


## 얼굴 합성 에이전트의 실제 단계 연결 — 신규 소스 범위

- 얼굴 합성 에이전트 하나가 원본/기준 프레임 분석, 사용자의 실제 후보 선택, 미리보기 생산, 명시적 미리보기 확인, 전체 처리와 결과 검증을 소유한다. 내부 도구나 review를 별도 public agent로 노출하지 않는다. 한 얼굴이어도 자동 선택/승인하지 않는다.
- 사진·대상·설정·저장 workflow·실행기 revision을 고정하고 실제 accepted 결과와 서버의 선택/확인 기록만 다음 단계의 근거로 사용한다. 분석이나 파일 존재만으로 render 준비를 주장하지 않는다. 만료/불명/실패/취소는 자동 재실행으로 해결하지 않는다.
- 기존 입력 검사와 native v2 의미는 보존한다. 새 face-only v3 capability가 실제 새 runtime revision에 결속되지 않은 현재 실행기는 held다. 이번 구현은 source/offline이며 실제 GPU·미리보기·합성·배포 허가가 아니다.

- 소스에서는 기존 편집기 저장/이력 복원, normal 입력 preview/Create/첫 Start 계획, 분석 결과 기반 두 사용자 대기와 최종 publication까지 연결했다. 정상 v3 binding fixture만 첫 분석을 허용하고 v2-only binding은 시작 불가 사유를 보존한다. 운영 runtime 활성화·실제 인물 분석/미리보기/합성은 검증하거나 수행하지 않았다.
