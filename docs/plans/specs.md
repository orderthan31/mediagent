# 미디에이전트 제품 기획

## 목표 단위 에이전트와 하위 툴

전사 에이전트는 시간 정보가 맞는 전사문 완성, 번역 에이전트는 원문 구간·순서·시각을 유지한 대상 언어 번역문 완성을 책임진다. 단일 업무이거나 순서가 정해졌다는 이유로 업무 전체를 툴로 분류하지 않는다. 구간 준비·모델 호출·구간 확인·결과 합치기는 에이전트가 허용된 툴허브에서 사용하는 하위 기능이다. 모델 주도 자율 선택은 업무 에이전트 등록과 별개다.

## 현재 툴 연결 경계 — 표준 정의 채택

LangGraph와 기존 CPU/큐/저장/복구/수명주기를 유지한다. 에이전트-facing 호출은 등록 실행기에 바인딩된 LangChain StructuredTool/BaseTool 및 Pydantic/JSON Schema 입력으로 제공한다. 임시 invoke(identity, request, execute_callback)와 설명 맵은 공개 규격이 아니다. CPU 이미지에는 LLM 프레임워크를 강제하지 않는다. 실제 설치된 langchain-core 1.7.0·Pydantic 2.14.1 조합을 검증하며 설치/업데이트는 수행하지 않는다.

MCP는 외부 런타임 연결이 필요한 경계에 한정한다. 현재 MCP SDK와 langchain 패키지는 설치돼 있지 않으므로 MCP 호환 완료를 주장하지 않으며 독자 MCP/RPC 서버나 새 ingress를 만들지 않는다. 추후 공식 SDK/호환 어댑터의 클라이언트 목록·스키마·호출·결과를 실제 확인한 뒤 판정한다. A2A·새 플랫폼/DSL·워크플로우 노드 노출은 범위 밖이다. 표시명은 '음성 구간 분석'이다. 표준 호출 연결과 자율 선택은 별도다.


## 현재 승인: 에이전트 허브와 툴허브

에이전트 허브는 오케스트레이터·에이전트·툴허브·컨트롤넷을 묶는 논리 계층이다. 기존 영상·음성·모델 처리를 툴로 제공하고 허용된 호출자는 공통 툴허브를 통해 기능과 입출력을 조회·실행한다. 실행·저장·복구와 온디맨드 수명 관리는 재사용한다. 허브 연결은 자율 판단 구현과 구분하며 고정 실행기를 자율 에이전트로 표시하지 않는다.

툴 목록·상세와 허용 툴 연결을 제공한다. 워크플로우 편집기에서 툴 노드의 추가·노출·숨김·유형 전환은 결정 유보이며 이번 변경에 포함하지 않는다. 기존 정의·작업을 자동 변경하거나 수동 재작성을 요구하지 않는다.


## 목적

현재 확정된 제품 컨셉과 주요 기능을 관리한다. 세부 동작과 구현 상태를 중복 나열하지 않는다.

## 현재 상태

워크플로우 기반 미디어 처리 제품으로 리뉴얼 중이다. 단일 인코딩의 실제 운영 제어·영속 대기/전송 보호와 관리자 처리 확인 화면은 운영 반영됐다. 인증 사용자 공용 읽기/다운로드는 API·UI·격리 설치본 검증까지 진행했으며 운영 반영/보존 원본 이관은 별도다. 일반 모델 API/폴백·다중 실행기/실제 분산·순수 제품 UI 전체까지 완성된 것은 아니다. 상세 상태는 태스크와 구조 문서에서 관리한다.

## 주요 내용

- 일반 사용자 기능은 원본과 작업 영역으로 한정한다. 워크플로우·에이전트·서빙·시스템·계정 관리 등 나머지 관리 영역은 관리자 전용이다.
- 로그인한 사용자 모두 원본과 작업·중간/최종 결과를 업로더·실행자와 무관하게 조회·사용·다운로드한다. 계정은 행위자/감사 기록이며 공용 미디어의 분리 경계가 아니다. provider credential과 관리자 설정 권한은 자료 공유와 별도로 보호한다.
- 에이전트 활성화·비활성화와 실행 인스턴스 수 변경은 서버 전체에 적용하는 관리자 운영 제어이며 사용자별 설정으로 제공하지 않는다. 메뉴·화면 접근과 서버 API 권한을 같은 기준으로 제한한다.
- 작업 하나는 원본 하나와 저장한 워크플로우 하나의 실행이며 티켓번호로 식별한다.
- 각 실행의 ticket ID 아래 manifest와 단계별 중간/최종 산출물을 정리한다. 공용 원본은 별도 원본 ID 경로에 보존하고 티켓에서 참조한다. 기존 CAS object와 읽기 호환은 삭제하지 않는다.
- 원본은 검증된 미디어와 순수 메타데이터로 관리한다. 원본 상세를 작업·서빙 설정 화면으로 사용하지 않는다.
- 업로드 영상과 작업 결과 영상은 원본을 보존하며 웹 전용 WebM을 따로 만든다. 플레이어는 WebM을 재생하고 원본과 WebM은 각각 다운로드할 수 있다.
- 워크플로우는 독립 에이전트와 제어 노드의 조합이다. 각 에이전트는 개별 진입점과 입력/설정/출력 계약을 갖는다.
- 에이전트의 명령·결과 전달은 RabbitMQ adapter로 분리하고 전체 workflow와 다음 단계 판단은 애플리케이션이 소유한다. 공통 실행 의존성을 재사용하면서 에이전트별 실행·확장 경계를 유지한다. 운영 연결 완료를 뜻하지 않는다.
- 에이전트 상세에서 해당 종류의 활성화·비활성화와 실행 인스턴스 수를 관리한다. 얼굴교체 등 선택 에이전트를 사용하지 않아도 다른 에이전트를 이용할 수 있어야 한다.
- 같은 종류의 에이전트를 여러 인스턴스로 실행하고 작업을 분산할 수 있어야 한다. 이 운영 관리 요구는 확정되었으나 현재 CLI·정보 상세가 구현 완료를 의미하지는 않는다.
- 서빙에서 공급자 연결·등록 모델을 관리하고 모델을 사용하는 워크플로우 노드가 호환 자원을 선택한다.
- 모델을 쓰는 태스크는 주 모델과 선택적인 동적 폴백 목록을 추가·삭제·재정렬할 수 있다. 저장/재열기와 티켓 snapshot에 순서가 유지되며, 지원 능력·인증·비용 승인을 확인한 후보를 순서대로 유한 시도한다. 취소는 전환하지 않고 중단하며 전 후보 실패는 태스크 실패다. 각 후보의 시도/실패 이유/전환/최종 성공 모델을 기록한다.
- 작업 상세에서 고정된 정의와 입력, 노드 상태·결과·사람 검수·명시 실행과 복구를 관리한다.
- 처리 여부가 불명확한 작업은 원 사실을 성공/실패로 덮지 않고 별도 확인·판단 기록과 보류 사유를 제공한다. 명시 지원 범위와 종료 근거를 검증한 뒤에도 새 준비 작업만 연결하며 별도 계획/동의/실행 승인을 요구한다. 늦은 원 결과는 격리·다운로드로 보존한다.
- 웹/애플리케이션의 제어와 에이전트의 처리, DB의 메타데이터와 오브젝트 스토리지의 미디어를 분리한다.
- 공통 검수 화면이 데이터 계약을 해석한다. 새 에이전트마다 전용 검수 화면을 만들지 않는다.

## 미확정 사항

비활성화/축소의 기본 순서는 새 작업 배정 중단→진행 작업 완료→정상 중지다. 제한시간/강제중지·다른 역할/다중 슬롯 확장은 [미확정 기획](ideation.md)에서 구분한다. 관리자 전용 권한과 원 사실 보존·모호한 상태의 자동 해제 금지는 확정이다.
