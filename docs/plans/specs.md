# 미디에이전트 제품 기획

## 목적

현재 확정된 제품 컨셉과 주요 기능을 관리한다. 세부 동작과 구현 상태를 중복 나열하지 않는다.

## 현재 상태

워크플로우 기반 미디어 처리 제품으로 리뉴얼 중이다. 전체 기능 완성이나 운영 전환을 의미하지 않는다.

## 주요 내용

- 일반 사용자 기능은 원본과 작업 영역으로 한정한다. 워크플로우·에이전트·서빙·시스템·계정 관리 등 나머지 관리 영역은 관리자 전용이다.
- 로그인한 사용자 모두 원본과 작업·중간/최종 결과를 업로더·실행자와 무관하게 조회·사용·다운로드한다. 계정은 행위자/감사 기록이며 공용 미디어의 분리 경계가 아니다. provider credential과 관리자 설정 권한은 자료 공유와 별도로 보호한다.
- 에이전트 활성화·비활성화와 실행 인스턴스 수 변경은 서버 전체에 적용하는 관리자 운영 제어이며 사용자별 설정으로 제공하지 않는다. 메뉴·화면 접근과 서버 API 권한을 같은 기준으로 제한한다.
- 작업 하나는 원본 하나와 저장한 워크플로우 하나의 실행이며 티켓번호로 식별한다.
- 각 실행의 ticket ID 아래 manifest와 단계별 중간/최종 산출물을 정리한다. 공용 원본은 별도 원본 ID 경로에 보존하고 티켓에서 참조한다. 기존 CAS object와 읽기 호환은 삭제하지 않는다.
- 원본은 검증된 미디어와 순수 메타데이터로 관리한다. 원본 상세를 작업·서빙 설정 화면으로 사용하지 않는다.
- 업로드 영상과 작업 결과 영상은 원본을 보존하며 웹 전용 WebM을 따로 만든다. 플레이어는 WebM을 재생하고 원본과 WebM은 각각 다운로드할 수 있다.
- 워크플로우는 독립 에이전트와 제어 노드의 조합이다. 각 에이전트는 개별 진입점과 입력/설정/출력 계약을 갖는다.
- 에이전트의 명령·결과 전달은 RabbitMQ adapter로 분리하고 전체 workflow와 다음 단계 판단은 애플리케이션이 소유한다. 공통 실행 의존성을 재사용하면서 에이전트별 실행·확장 경계를 유지한다. 운영 연결 완료를 뜻하지 않는다.
- 에이전트 상세에서 해당 종류의 활성화·비활성화와 실행 인스턴스 수를 관리한다. 얼굴교체 등 선택 에이전트를 사용하지 않아도 다른 에이전트를 이용할 수 있어야 한다.
- 같은 종류의 에이전트를 여러 인스턴스로 실행하고 작업을 분산할 수 있어야 한다. 이 운영 관리 요구는 확정되었으나 현재 CLI·정보 상세가 구현 완료를 의미하지는 않는다.
- 서빙에서 공급자 연결·등록 모델을 관리하고 모델을 사용하는 워크플로우 노드가 호환 자원을 선택한다.
- 모델을 쓰는 태스크는 주 모델과 선택적인 동적 폴백 목록을 추가·삭제·재정렬할 수 있다. 저장/재열기와 티켓 snapshot에 순서가 유지되며, 지원 능력·인증·비용 승인을 확인한 후보를 순서대로 유한 시도한다. 취소는 전환하지 않고 중단하며 전 후보 실패는 태스크 실패다. 각 후보의 시도/실패 이유/전환/최종 성공 모델을 기록한다.
- 작업 상세에서 고정된 정의와 입력, 노드 상태·결과·사람 검수·명시 실행과 복구를 관리한다.
- 웹/애플리케이션의 제어와 에이전트의 처리, DB의 메타데이터와 오브젝트 스토리지의 미디어를 분리한다.
- 공통 검수 화면이 데이터 계약을 해석한다. 새 에이전트마다 전용 검수 화면을 만들지 않는다.

## 미확정 사항

에이전트 비활성화/축소 중 작업 처리 및 운영 제어 방식은 [미확정 기획](ideation.md)에서 구분한다. 관리자 전용 권한과 적용 범위는 확정이다.
