# 미디에이전트 제품 기획

## 확정 추가 범위: 에이전트 전용 워크플로우와 실제 소스 계층

- 만들 것: 전사 → 한국어 번역 → 자막 영상 제작의 업무 에이전트만 저장/편집/실행 캔버스에 둔다. 분석·오디오 준비와 구간 처리는 전사 내부 도구, 자막 생성·번인·검사는 영상 제작 내부 도구다. 오케스트레이터는 에이전트 간 순서·배정·준비를, 에이전트는 자기 도구 선택·순서·결과 확인을 책임진다.
- 사용: 영상과 등록 모델을 고르고 시작한다. 에이전트 상세에서 하위 도구의 진행·출력·실제 콘솔을 본다. 오류는 붉은 노드/이유로, 다음 실행기 실제 준비는 연결선의 ‘다음 단계 준비 중’과 대상 노드의 ‘준비 중’으로 구분한다. 내부 도구 준비는 에이전트 내부 진행이다.
- 소스: 기존 모노레포 안에서 오케스트레이터 구현·업무 agents·tools/툴허브·runtime/컨트롤넷을 실제 이전한다. 기존 import/CLI의 필요한 경계는 구현 없는 호환 모듈로 유지하며 원본 구현을 복제하지 않는다. 패키지·Docker·실행 진입점과 전후 트리를 함께 검증한다.
- 확인 경계: 새 작업·30/31 재실행·실모델/provider·유료/GPU 호출·새 검증계 없이 기존 개발계 빌드/시작과 화면, 네트워크 없는 결정/상태 회귀를 검증한다. 과거 작업 snapshot·실행·결과·불명 원장은 그대로 보존하고 과거 화면의 집계 투영과 새 실제 에이전트 실행 계약을 구분한다.
- 외부 통신: 승인 1565553471640572038의 범위로 전사/번역 연결부만 기존 API 외부망에 연결했다. DNS·인증서 검증 TLS 1.3은 양쪽 성공, HTTP 요청 0, 기존 작업/실행/호출 원장 동일. 이는 전사 완주·품질 검증이 아니다.
- 미검증/미결정: 실영상 새 흐름 완주와 콜드부트 전환의 신규 실행 실증은 승인 범위 밖이다. 없는 과거 HTTP 상태·콘솔을 만들거나 불명 호출을 자동 재호출하지 않는다.


## 최신 정정: 콘솔 원문과 멈춘 작업 표시

로그 탭은 시작·종료 이벤트가 아니라 실행기·모델 연결부의 실제 stdout/stderr와 예외를 보여준다. 태스크별로 구분하고 인증정보를 가린 뒤 컨테이너 밖에 보존한다. 과거에 출력·저장하지 않은 로그는 없다고 표시하며 재실행으로 만들지 않는다. 완료·오류·대기 태스크 모두 출력/로그 탭을 유지한다. 확정 오류와 응답 불명 보류를 작업·태스크 화면에 구분해서 보여주되 원래 실행 기록과 재호출 방지는 보존한다. 시험 작업은 생성 근거로 현재 목록에서만 삭제하고 사용자 작업 20·21·30·31과 불명·감사·결과 기록은 남긴다. 새 시험 작업이나 모델 호출은 하지 않는다.

## 이번 요청: 한국어 자막이 입혀진 영상

사용자가 영상을 넣으면 전사문을 만들고 한국어로 번역한 뒤, 한국어 자막이 화면에 입혀진 MP4를 받는다. 사람 검수 단계는 넣지 않는다. 태스크 상세에서는 출력과 실제 로그를 나눠 확인한다. 테스트 자료는 현재 목록에서 삭제하되 과거 작업을 확인하는 데 필요한 자료와 이력은 보존한다.

## 무엇을 만드는가

전사 에이전트는 오디오를 준비하고 필요한 구간을 나눠 시간 정보가 맞는 전사문을 완성한다. 번역 에이전트는 문맥과 자막 시간을 유지해 번역문을 완성한다. 오디오 추출, 구간 분리, 모델 호출과 결과 합치기는 이 업무에 쓰는 도구다.

## 사용자는 어떻게 쓰는가

원본·모델·언어를 선택하고 작업 시작을 한 번 누른다. 진행을 확인한 뒤 자막과 영상을 내려받는다. 에이전트 목록·상세에서는 맡은 일, 현재 상태, 사용할 수 있는 도구와 수행한 작업을 확인한다.

## 실제로 확인한 범위

기존 개발 환경의 작업 #29에서 전사·번역을 거쳐 자막과 영상이 만들어지고 다운로드되는 것을 확인했다. PC와 좁은 화면에서도 목록·상세를 확인했다. 정해진 시험 응답으로 처리 흐름을 확인한 것이며, 실제 모델의 인식·번역 품질을 확인한 것은 아니다.

## 아직 결정하지 않았거나 확인하지 않은 것

도구를 워크플로우 편집기에 직접 배치할지는 나중에 결정한다. 모델이 매 단계에서 사용할 도구를 스스로 고르는 방식은 추가하지 않았다. 기존 워크플로우와 진행 작업은 유지하며, 실제 유료 호출이나 GPU 실행은 별도 승인 없이는 하지 않는다.

## 목적

현재 확정된 제품 컨셉과 주요 기능을 관리한다. 세부 동작과 구현 상태를 중복 나열하지 않는다.

## 현재 상태

기존 개발 환경에 전사·번역 에이전트와 목록·상세가 연결됐다. 작업 #29의 자막·영상 다운로드까지 확인했다. 전체 기능의 동등성, 실제 모델 품질과 여러 컴퓨터에 나눠 실행하는 검증까지 모두 끝난 것은 아니다. 자세한 완료·미완료 항목은 태스크 문서에서 구분한다.

## 주요 내용

- 일반 사용자 기능은 원본과 작업 영역으로 한정한다. 워크플로우·에이전트·서빙·시스템·계정 관리 등 나머지 관리 영역은 관리자 전용이다.
- 로그인한 사용자 모두 원본과 작업·중간/최종 결과를 업로더·실행자와 무관하게 조회·사용·다운로드한다. 계정은 행위자/감사 기록이며 공용 미디어의 분리 경계가 아니다. provider credential과 관리자 설정 권한은 자료 공유와 별도로 보호한다.
- 에이전트 활성화·비활성화와 실행 인스턴스 수 변경은 서버 전체에 적용하는 관리자 운영 제어이며 사용자별 설정으로 제공하지 않는다. 메뉴·화면 접근과 서버 API 권한을 같은 기준으로 제한한다.
- 작업 하나는 원본 하나와 저장한 워크플로우 하나의 실행이며 티켓번호로 식별한다.
- 각 실행의 ticket ID 아래 manifest와 단계별 중간/최종 산출물을 정리한다. 공용 원본은 별도 원본 ID 경로에 보존하고 티켓에서 참조한다. 기존 CAS object와 읽기 호환은 삭제하지 않는다.
- 원본은 검증된 미디어와 순수 메타데이터로 관리한다. 원본 상세를 작업·서빙 설정 화면으로 사용하지 않는다.
- 업로드 영상과 작업 결과 영상은 원본을 보존하며 웹 전용 WebM을 따로 만든다. 플레이어는 WebM을 재생하고 원본과 WebM은 각각 다운로드할 수 있다.
- 워크플로우는 독립 에이전트와 제어 노드의 조합이다. 각 에이전트는 개별 진입점과 입력/설정/출력 계약을 갖는다.
- 에이전트의 명령·결과 전달은 RabbitMQ adapter로 분리하고 전체 workflow와 다음 단계 판단은 애플리케이션이 소유한다. 공통 실행 의존성을 재사용하면서 에이전트별 실행·확장 경계를 유지한다. 운영 연결 완료를 뜻하지 않는다.
- 에이전트 상세에서 해당 종류의 활성화·비활성화와 실행 인스턴스 수를 관리한다. 얼굴교체 등 선택 에이전트를 사용하지 않아도 다른 에이전트를 이용할 수 있어야 한다.
- 같은 종류의 에이전트를 여러 인스턴스로 실행하고 작업을 분산할 수 있어야 한다. 이 운영 관리 요구는 확정되었으나 현재 CLI·정보 상세가 구현 완료를 의미하지는 않는다.
- 서빙에서 공급자 연결·등록 모델을 관리하고 모델을 사용하는 워크플로우 노드가 호환 자원을 선택한다.
- 모델을 쓰는 태스크는 주 모델과 선택적인 동적 폴백 목록을 추가·삭제·재정렬할 수 있다. 저장/재열기와 티켓 snapshot에 순서가 유지되며, 지원 능력·인증·비용 승인을 확인한 후보를 순서대로 유한 시도한다. 취소는 전환하지 않고 중단하며 전 후보 실패는 태스크 실패다. 각 후보의 시도/실패 이유/전환/최종 성공 모델을 기록한다.
- 작업 상세에서 고정된 정의와 입력, 노드 상태·결과·사람 검수·명시 실행과 복구를 관리한다.
- 처리 여부가 불명확한 작업은 원 사실을 성공/실패로 덮지 않고 별도 확인·판단 기록과 보류 사유를 제공한다. 명시 지원 범위와 종료 근거를 검증한 뒤에도 새 준비 작업만 연결하며 별도 계획/동의/실행 승인을 요구한다. 늦은 원 결과는 격리·다운로드로 보존한다.
- 웹/애플리케이션의 제어와 에이전트의 처리, DB의 메타데이터와 오브젝트 스토리지의 미디어를 분리한다.
- 공통 검수 화면이 데이터 계약을 해석한다. 새 에이전트마다 전용 검수 화면을 만들지 않는다.

## 미확정 사항

비활성화/축소의 기본 순서는 새 작업 배정 중단→진행 작업 완료→정상 중지다. 제한시간/강제중지·다른 역할/다중 슬롯 확장은 [미확정 기획](ideation.md)에서 구분한다. 관리자 전용 권한과 원 사실 보존·모호한 상태의 자동 해제 금지는 확정이다.

## 워크플로우의 LLM 선택
- 전사·번역 LLM의 정본은 워크플로우에서 고른 등록 모델 ID/revision과 요청 옵션이다. 업무 코드가 특정 LLM 이름·계열을 강제하거나 다른 모델로 바꾸지 않는다.
- 공급자 연결·키는 기존 계정별 저장 경계를 유지한다. 모델에 필요한 음성 입력·시간 정보·구조화 응답 기능이 없으면 사유를 알려 실행을 막는다.
- 공급자 변환은 모델 호출 툴 안의 LiteLLM SDK가 맡는다. 전사 분할·원본 시각 복원·한국어 번역·자막 번인과 에이전트 간 흐름은 기존 구조를 유지한다.
